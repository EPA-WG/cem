# JSON Schema source authoring

This ordinary Studio project authors a small note schema using the explicit
`application/schema+json` identity and
`https://cem.dev/ns/data/json-schema/1`. Open it under **Content types and schemas
→ Schema authoring** and clone it before editing. It uses shared source controls.

## Configurations

| Configuration | Purpose |
| --- | --- |
| `validate-schema` | Parse JSON Schema source and validate its Draft 2020-12 dialect declaration. |
| `format-schema` | Format through the native JSON Schema lifecycle writer and compare the complete expected source bytes. |
| `validate-data-syntax` | Parse `data/note.json` as ordinary JSON syntax only. |
| `repair-dialect` | Replace the unsupported Draft 7 dialect with Draft 2020-12. |

`schemas/note.schema.json` shows `$id`, object properties, `required`, a local
`$defs` declaration and `$ref` syntax. These keywords document an intended domain
contract; this release validates JSON parsing and the admitted dialect. It does
**not** assert keyword constraints against instance documents, resolve `$ref` or
`$dynamicRef`, traverse local definitions, load remote schemas, implement dynamic
scope or claim arbitrary draft support. No resolver is invoked by the example.

`data/note.json` is a separate ordinary JSON resource. Its syntax configuration
has no schema-package or domain-schema binding. Successful JSON parsing does not
mean the data satisfies the authored schema. Source and instance validation must
remain visibly distinct until a native instance-validator contract is available.

Parse/Inspect configurations are deliberately absent: the current shared source
routing can expose embedded generic CEM tokenizer errors despite a zero exit
status. Same-schema native formatting and schema-source validation work without
that projection. The source editor still supports editing these files.

## Failure, repair and edits

`failures/unsupported-dialect.schema.json` contains the same schema with a Draft 7
`$schema`. Native validation reports one `cem.json_schema.unsupported_dialect`
error at line 2, column 14, byte offset 15. Replace the dialect URI with
`https://json-schema.org/draft/2020-12/schema`; repaired bytes match the valid
schema exactly. The read-only failure remains unchanged when a saved copy is
repaired.

The native tabular formatter currently uses leading commas. Its complete output
is `expected/formatted-note.schema.json`, generated by the native CLI rather than
a browser-side JSON formatter. It is presentation text, never an AST handoff.

Change the saved schema title from `Note` to `Saved note`, validate and format
again; the formatted result should reflect the saved revision. Edit the separate
JSON data title independently and rerun syntax validation. A second clone can
carry a different schema title without changing the first project.

Saved source validation, formatting and repaired resources rerun offline using
Studio's normal project/cache mechanism. Acceptance uses temporary copies and
isolated storage, preserves user projects/drafts, and does not change credential
privacy or enable automatic recovery.
