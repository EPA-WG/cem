## Evidence and preserved limits

The audit checks README/resource/configuration references and complete workflow
coverage. Native grammar, data imports, validation and execution stay in Rust;
this tool does not parse project data or interpret native ASTs. README prose is
reviewed against the native fixtures and [format limits](studio-content-types.md).

The native Feature Tour verifier records all declared configuration executions.
Native Inspect verifies its original output and exit separately from a companion
diagnostic view; that view does not prove the retained AST failed or was clean.
Exact native Parse and companion-view limits remain explicit in acceptance evidence.
Declared configurations therefore do not imply uniform clean native execution.
Parse/Inspect coordinate presentation is distinct from owned source-map
publication; explicit projection JSON is an export boundary, never an internal
AST handoff. AST JSON shape, output-only adapters and header-only validation
limits remain documented in the relevant project READMEs and [TODO](todo.md).

Generated Schema examples, Feature Tour and starter READMEs are ordinary Markdown
resources. Existing project/source IDs and starter default selection remain
stable; cloned documentation is independent of catalog originals. Reusable UI
stays declarative in shared CEM components. Entered passwords/one-time codes
block recovery until explicitly cleared; automatic whole-Studio recovery remains
disabled. Saved projects and drafts are not cleared by this audit.
