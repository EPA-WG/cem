### Required split boundaries

1. **CSV is not freely optional today.** [packages/cem-components/src/components/cem-data-view/cem-data-view.xhtml](../packages/cem-components/src/components/cem-data-view/cem-data-view.xhtml)
   calls `data:read(value, format)`; the [packages/cem_ql/src/eval/data.rs](../packages/cem_ql/src/eval/data.rs)
   evaluator delegates to [packages/cem_ml/src/import.rs](../packages/cem_ml/src/import.rs) for JSON/CSV.
   Keep required importers in core until native requirement/yield and typed tree
   handoff work. `cem-table` itself is structural markup/slots, not a CSV parser.
2. **Syntax coloring is a component capability.** `plaintext-editor` calls the
   shared native highlighting endpoint. Deferring language tooling must retain
   typing, selection/IME, highlighting correctness and original diagnostics.
3. **The entry/facade and native exports need profile-specific roots.** Hiding
   wrappers or moving schema bodies does not remove compiled implementations.
   Legacy/XSLT and XPath function-library paths are present in the shared facade.
4. **Controls, CSS, typed data and recovery are mandatory.** Memory, admission,
   inventory and checkpoint exports cannot be classified as optional debug code.
5. **No component removal proof is implied.** Slots, providers, expressions and
   external templates remain dynamic extension points across the catalog.

## Limits and next proof

- Metadata/import edges are conservative source evidence, not a complete Rust call graph or proof of removability.
- Named function libraries, runtime providers, slots and computed imports require native demand/handoff proof.
- Literal native includes are hashed; generated/computed includes and source scanners are not a complete compiler build-input manifest.
- WASM code/data sections are measured bytes, not attribution to a crate, language or removable source pack.
- Audited source hashes and artifact/optimizer hashes are distinct evidence; this script is not a complete reproducible-build attestation.
- No reduced profile exists yet; native live/linear memory and browser costs must be measured separately.

No new JavaScript UI behavior, parser or component implementation is introduced.
The current full-runtime defaults, credential recovery refusal and 4 MiB
checkpoint/deadline contracts remain unchanged. Continue with the measured
browser baseline and native module/handoff prototype in the
[profile checklist](../docs/todo.md#component-application-wasm-profile-separate-target).
