# SSR source/page/base/output URL preflight — 2026-11-05

The shared native `cem_ml::ssr_route` module now preflights an entire batch of
HTML page routes before execution. `SsrPageRoute` borrows its original native
HTML owner, retains source URI spelling and provenance, and separately records
canonical deployed page URL, effective document base and optional output URI.
No source serialization/reparse, AST handoff, authored script execution, resolver
dispatch or output write occurs. The original importer owns decoded attributes,
namespace/depth events and generated-source origins.

Page URLs require absolute HTTP(S), without credentials or fragments (including
an empty fragment). WHATWG URL normalization detects host/default-port/dot-path
aliases while preserving query and trailing-slash distinctions. Source and
output addresses require prepared absolute URIs without credentials/fragments;
host-defined schemes and in-memory destinations remain possible. Host path-to-URI
lowering is explicit. Duplicate normalized page URLs or output URIs reject the
batch, with route and first-route indexes; the limit is 1,024 routes. Errors
omit invalid authored address values from diagnostic control metadata.

The URL portion of render identity includes source, page and effective base,
excluding physical output. It is not the complete cache/adoption key. Separate
request helpers retain source-input reads, public page-resource reads and output
writes. Existing resolver policy and explicit public-to-local read maps still
decide admission: substitutions do not rewrite public identity or source maps,
and denials still win before dispatch.

The first HTML `<base href>` in the document tree selects the base; later bases
cannot replace it. Template fragments, foreign bases, target-only bases, comments
and script text do not select it. Decoded entities, duplicate attributes, empty
values, relative URLs, default ports, queries and base fragments are covered.
The selected native attribute map is retained exactly, including transformed
origins; unmapped generated bytes acquire no fabricated source frames.

The [HTML Standard](https://html.spec.whatwg.org/multipage/semantics.html#the-base-element)
specifies page fallback for an unparseable first base. Chromium 148 and Chrome
155 instead expose `about:blank` in the invalid-first-base fixture. This
increment refuses that case with `cem.ssr.base_url_invalid` rather than approving
a different browser identity or selecting a later base. `data:`/`javascript:`
bases retain page fallback. Credential-bearing bases are refused.

The initial static profile refuses fragment owners, parser recovery,
self-closing non-void HTML, `noscript` and non-UTF-8 encoding metadata. Those
profiles require an extended native import/browser-state contract. A selected
base plus CSP meta requires an explicit host `Allowed`/`Blocked` decision;
header CSP likewise belongs to the host decision. `Unspecified` asserts no
effective header CSP. This module neither evaluates CSP nor grants resource
access from a syntactically valid URL.

The [implementation contract](../cem-ml-cli-ssr-proposal.md#311-implemented-native-url-preflight)
and crate README name these limits. Ordinary transform `pageUrl` parameters are
unchanged. No SSR command, page coordinator, lifecycle/island execution, render
artifact, source adapter or hydration-ready output is introduced. Next is the
retained native SSR artifact contract, followed by the first shared inline
declaration lifecycle and adoption slice.

Validation receipts and exact browser URL observations are retained in the
[adjacent receipt](ssr-route-preflight-2026-11-05.json). Ten native cases failed
against the stub before implementation; the unsupported-profile case also failed
before its admission guard. Native tests cover atomic refusal, output-independent
identity, source/config/generated mappings, resolver substitution/denial and the
exact 1,024-route boundary. The browser check uses the same explicit JSON test
vectors, disables authored JavaScript and allows no external resource requests;
it compares browser URL state rather than implementing JavaScript URL routing.
