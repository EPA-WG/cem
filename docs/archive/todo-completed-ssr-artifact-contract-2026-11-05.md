# Retained native SSR artifact contract — 2026-11-05

`cem_ml::ssr_artifact::CemSsrPageArtifact` now retains the original native HTML
source and the existing native DOM projection in an immutable typed envelope.
Construction requires the exact preflight source owner. HTML projections retain
that same `Arc`; CEM DOM projections retain their existing `Arc<CemDocument>`
alongside the original HTML source. Other bodies and substituted HTML owners
are refused. Native extension handoff preserves the owners without source
serialization, reparse, JSON AST handoff or a second DOM representation.

Route metadata keeps all source/page/base/output addresses and original config
and base provenance, including selected native event and host base-policy
decision. Whole-source maps come from the native owner. Generated bytes with
no admitted mapping remain unmapped. The envelope has no deserializer or public
transition that can promote report metadata into native lifecycle authority.

Only unrendered and partial lifecycle states exist in this increment. The typed
adoption record names expected lifecycle, island and render-plan versions and
always reports `hydrationReady=false`. Partial reasons include missing
participants/capabilities, cancellation, exhaustion and incomplete work. A
complete input key does not authorize adoption. A future ready state needs an
actual coordinator-owned proof of admitted islands, fresh policy and matching
render boundaries; there is no fixture-only successful-render path.

Settle policy is explicit and has no default grant. Supported ceilings are
depth 64, 4,096 instances, 64 render passes, 1,024 resources, 64 MiB acquired
bytes, 60,000 ms wall time and 60,000 ms CPU time; all limits must be positive.
Initial accounting includes original source bytes. Counters cannot decrease or
hide exhaustion. Explicit exhausted partial state may report counters beyond
the limits, while remaining non-adoptable. Static fallback requires its explicit
policy flag and partial state; it remains subject to normal publication and
policy checks. Unrendered work never becomes a static-publication candidate.

The envelope validates limits and observed counters; the future coordinator
must enforce acquisition/deadline budgets. This is not an allocator or a timer
for an already-retained DOM. Existing startup deadlines, resource/credential
policy and UI behavior are unchanged. Control metadata is limited to 1 MiB and
256 diagnostics; escaped strings are bounded before excess output allocation.
Nonempty protocol identity fields have a 4,096-byte ceiling.

Deterministic render-input identity reuses the native `DependencySnapshot`
contract. It requires a complete render closure, every effective input/provider
stamp, content hashes for source dependencies and a root URI/MIME/schema/hash
matching the retained HTML source. Its structured metadata also covers deployed
page/base and base policy, compiler/lifecycle/island/render-plan versions,
entrypoint, native parameter hash, source-map mode, DOM-safe formatter profile
and settle policy. Output destinations and measured consumption/time are
excluded. Delimiter-containing values cannot alias another tuple.

These are conservative input keys, not DOM result certificates or cache reuse
grants. Unrendered and partial envelopes can have the same input key and remain
non-adoptable. Pending, opaque, incomplete, source-mismatched or invalid dependency
closures have no key. Native producers still own complete dependency and policy
fingerprints; key equality does not skip fresh evaluation or resource admission.

`export_report_json()` names an explicit diagnostic-control boundary. It exports
route/provenance, policy/usage, adoption status, candidate identity or refusal and
diagnostics, with no DOM or original source text. Retained diagnostic origins
stay available; source-map mode names the requested render identity and does
not erase native provenance. The report is not the browser data island,
production omission/redaction policy, default CLI presentation or a native AST
handoff. Existing CEM-ML Inspect/report defaults remain unchanged.

The envelope reserves `application/vnd.cem.ssr-page+cem-bin`,
`https://cem.dev/ns/projection/ssr-page/1` and native representation
`cem.ssr-page`. It does not provide a wire codec, schema-package parser admission,
default encoder, CEMT evaluator flattening or converter. The SSR command,
coordinator, per-instance island/style/range records, completed artifact and
browser hydration remain pending. The contract is documented in the
[proposal](../cem-ml-cli-ssr-proposal.md#51-implemented-retained-envelope-and-admission-limits)
and crate README; the next task is the first shared inline-declaration native
lifecycle/admission slice.

The expanded fourteen-case suite covers native owner retention, foreign-owner
and body refusals, source/config/generated maps, explicit bounded reports,
policy and progress guards, all seven exhaustion counters, incomplete identities,
output-independent keys, protocol/provider/declaration sensitivity and delimiter
aliases. No authored page script or JS rendering adapter is involved.
