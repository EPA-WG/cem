## Module-map contract

Standalone module-map v1/v2/v3 validation previously stopped at JSON syntax.
The native lifecycle now applies the explicitly selected deployment-map contract
before source tooling or formatting can consume an admitted map. Selected schema
and embedded `$schema` must agree; MIME-only module maps select v1. A `$schema`
property in ordinary JSON cannot elevate its source identity.

A shared native decoder and pure checks enforce exact bare identities, versioned
import/resource shapes, supported content types, path-extension agreement,
identity collisions and declared v3 module edges. Only JavaScript can declare
edges, and edge targets must be declared JS/JSON modules. No map asset is read
by source admission. Diagnostics use the original JSON key/value range, URI,
UTF-8 byte offset, line/column and source map, with a field path when available.
Missing members can retain their containing native range rather than inventing
a character location.

Graph planning confirms paired schema/key identities before shared asset
validation, preserving its existing diagnostic ordering. Pair agreement, target
containment, read grants, explicit resource access and bounded JavaScript
rewriting remain planning operations. Ordinary unversioned browser import maps
and input-root-scope alias maps retain their separate contracts.

`module-maps` 1.0.2 adds `repair-semantic-v1`, `repair-semantic-v2` and
`repair-semantic-v3`. Each repairs a syntactically valid relative asset key back
to the exact valid map after an original semantic diagnostic. The existing
syntax repairs, independent deployment builds, last-good artifacts and offline
saved copies remain in the same ordinary project. The older invalid v2 resource
kind and v3 embedded-version fixtures now refuse standalone source validation;
the v1 trailing-slash identity also refuses source validation. The v1 planner
still reports the paired-key mismatch first, preserving its original priority.

## AST JSON contract

Explicit AST conversion used the CEMT presentation subject, an array with text
`value` fields. The registered semantic AST source validator expects a document
object and text `data`. The validator is unchanged.

`projection::ast_json` now exports the native semantic document envelope, sharing
native node projection with DOM JSON. Expanded-name namespaces, ordered
attribute `valueNodes`, reference expressions/context/targets, original ranges
and source maps are preserved. Non-owning target handles may repeat or cycle;
export does not follow them. The actual project fixture was regenerated by the
native CLI and accepted directly by the registered source validator.

CEM-ML Parse/Inspect and their optional `parse --format ast-json` CEMT subject
remain a separate inspection contract. Binary projection bytes and runtime
ownership are unchanged. Old array exports must be regenerated from original
source for semantic interchange. JSON source-shape validation is a structural
round trip, not native owner decoding, executable replay, integrity verification
or an admitted source-navigation endpoint. Projection input adapters and full
binary payload validation remain on the active TODO.

`native-projections` 1.0.1 adds `validate-ast-export`, validating the actual native
export alongside the existing authored AST fixture. It needs no JavaScript
wrapper, field rewriting or relaxed source validation.
