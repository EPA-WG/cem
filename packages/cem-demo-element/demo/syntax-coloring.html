HTML, CEM-ML, and CSS syntax coloring

This decision page puts HTML event/markup-token families, CEM-ML tokenizer families, and CSS lexical and grammar-owned semantic contexts on one palette. It is intentionally broad: use it when changing role assignments, theme mappings, or contrast.

Branded light palette.

Contrast light and contrast dark are included because they are public CEM theme modes. Today syntax colors intentionally share the corresponding light/dark emotional endpoints; keeping them here exposes any future mode remapping. Operating-system forced colors remain a separate browser setting.

Variable-like identifiers and attributes receive the strongest scan color, --cem-action-destructive-pending-background. Tag names receive the next emphasis level from --cem-action-primary-active-background, while keywords use --cem-action-primary-pending-background and strings use --cem-action-contextual-pending-background. Invalid source and error diagnostics use --cem-action-destructive-hover-background.

CSS property keys use an IDE-inspired red/light-blue pair; ordinary values use blue/peach. CSS functions use a gold pair. These colors remain explicit when no close CEM emotional token exists.

The rendered source uses native elements as its compact visual vocabulary: <b> for tags, <var> for attributes and variables, <dfn> for CSS properties, <data> for CSS values, <kbd> for CSS functions, <strong> for keywords, <i> for strings, <u> for numbers, <small> for comments, <samp> for source text, and <mark> for errors. Only the enclosing <code> carries classes; punctuation and raw source remain unwrapped.
