Override a data cell with template matching

Import the viewer, replace one presentation

The first two examples own small templates that import the existing data viewer, declare one template @match rule, and call base.viewer. The viewer dispatches a cell's retained source node through apply-templates @mode=cell. Its @match=true rule produces the default td; a matching local rule can replace the whole cell.

The first sample includes its entire template inline. Its rule is simply node.name == "name" in cell mode: node is the original <name> element. Matching supplies node automatically; it needs no parameter declaration. The source is an implicit module: imports and matching rules are declarations; other content runs in source order. Neither module nor body wrappers are needed. A rule selected only by matching needs no @name. The replacement cell contains an image plus the original name. {$node} reuses the name subtree in the label. The image attribute projects that same native value to text. Use {$dom:text(node)} when only text is wanted. dom::chain(node).parent() finds its row; searching that parent's children finds the sibling <id> for the image. No heading, row or ID is passed to the matching template. Other fields keep the imported presentation.

The separate stock rule demonstrates a content override in inspect mode, keeping the default cell. It uses a narrower condition: /catalog/product/stock with trimmed text 0. Its CEM-QL predicate checks namespaces and data:node_key membership in that source path, so a reference branch's stock stays ordinary.

Editing, table discovery, columns, sorting and row selection all come from the base viewer. The first sample replaces cell generation; the second replaces matching content within a cell. CEM-ML imports the source into a retained CEM tree; presentation leaves that source intact. Edit the source, then Tab out to rerender.

Single-node cells use cell mode. Missing values, repeated values sharing a column, attributes and direct row text keep the base viewer's grouped cell generation. Missing values show ∅, and empty text shows "". The default cell rule delegates its source node to inspect mode.

The sibling lookup selects the first sibling named id in source order, comparing only its local name. The empty-name fallback skips nameless nodes such as whitespace. If no ID is present, the name still renders without an image. This example uses a complete retained tree; it does not consume an unfinished document stream. The existing import and query limits apply.

The Pokémon sample supplies an ID beside each name and uses the two bundled images, IDs 2 and 3. These local SVGs come from the same pinned sprite package used by the HTTP demo; see the image sources and attribution. cem-module-url resolves their directory relative to the declaration, including when this page is source-loaded.
